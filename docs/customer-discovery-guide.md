# 历史记录：Physical Context Runtime 开发者访谈

状态：旧 B2B/SDK 假设的访谈草案。当前面向普通消费者的研究以 [消费者问题访谈指南](consumer-discovery-guide.md) 为准。

目标：两周内判断设备开发团队是否有重复、昂贵且有预算的持续视觉状态/事件问题。访谈不是产品推介，也不能用“你会不会用”代替真实经历。

## 找谁谈

优先联系过去 12 个月实际做过 camera-enabled AI、Jetson/ARM edge vision、智能摄像头、机器人视觉或多模态硬件的：

- 创始人、产品负责人、嵌入式/边缘 AI 技术负责人。
- 负责摄像头管线、CV 推理、设备运维或 agent integration 的工程师。
- 有近期项目交付经历的小型方案集成商。

目标 12 人，至少 8 人属于设备/摄像头/边缘 AI 团队。桌面姿态用户可以补充访谈，但不能替代目标买方。

## 访谈开场

“我在研究摄像头型 AI 设备从实时视频生成可靠状态和事件的工程过程。我现在不推销产品，想了解你们最近一次项目里具体怎么做、花了多少时间、哪里最难。可以聊 20 分钟吗？”

## 核心问题

从最近一次具体项目往回问：

1. 最近一次需要从摄像头连续判断状态或事件的项目是什么？设备、摄像头、模型和上线时间分别是什么？
2. 从接通摄像头到能够稳定交付，具体做了哪些步骤？哪一步最耗时？
3. 状态需要跨多少时间理解？如何处理漏检、遮挡、低置信、断流和设备重启？
4. 现在如何保存、查询和解释一次状态变化？谁会用这些结果？
5. 这部分由谁负责，累计投入了多少工程时间？是否造成过延期、返工或客户验收失败？
6. 当前方案由哪些组件组成？哪些部分买了、开源了、自己维护了？为什么？
7. 哪些数据必须留在设备本地？现有隐私、保留和删除要求是什么？
8. 如果完全不解决这件事，会发生什么？过去有没有预算或采购项目处理它？
9. 谁会批准工具或 SDK 预算？评估周期、采购门槛和可接受的试点费用是什么？
10. 我可以在你们下一次真实项目/设备上观察一次集成，或拿一个脱敏的输入和验收目标做试验吗？

避免先展示方案。若受访者只评价概念好不好，追问：“上次你遇到这个问题是什么时候？当时怎么解决？投入了什么？”

## 判定方法

### 强信号

- 能讲出最近一次具体项目，而非泛泛认同愿景。
- 多家公司独立提到相同的时间状态、异常恢复、回放证据、隐私或设备适配痛点。
- 当前 workaround 造成可量化工程工时、延期或验收问题。
- 受访者愿意提供样机、数据、引荐预算决策者或设定付费试点步骤。

### 弱信号

- “听起来不错”“AI 很有前景”“如果免费会试试”。
- 只希望加一个 dashboard、再接一个 detector，已有工具几小时即可完成。
- 痛点只由创始人自己遇到一次，其他团队没有复现。
- 付费者、采购来源和试点时间始终说不清楚。

### 两周决策门槛

- **继续验证 Runtime：**12 人中至少 5 人在最近一年遇到重复的持续状态/事件管线问题；至少 3 人愿意给真实场景/测试设备；至少 2 人愿意讨论有金额和日期的试点。
- **收窄垂直场景：**有痛点但只在一个行业/事件中重复，且买方明确。只围绕这个工作流做试点，不做通用 SDK。
- **停止当前商业假设：**没有重复痛点、没有成本或预算信号，或需求都能由现成 SDK 快速满足。继续把 Jetson 工程作为技术作品可以，但不要把它称为已验证创业方向。

## 对外联系节奏

先由创始人通过已有职业关系、Jetson/边缘 AI 社区、硬件创业社区和开源项目维护者寻找访谈对象。每次只请求 20 分钟问题访谈，不群发产品宣传。未经明确许可，不上传或分享受访者的设备视频、代码或业务细节。
