# 身体小图与外观身份匹配

实时链路：检测到猫 → 裁剪检测框 → JPEG 小图 → 身体外观描述子 → 本地注册库匹配 → 连续确认 → 网页显示名字。当前一次只展示单只猫，检测到多只猫时清空身份小图并提示无法区分。

## 启用

```bash
coco-context --source csi --model /path/to/raw.engine --pet-gallery data/gallery.json
```

注册库继续使用 Python 原型 `build_gallery.py` 生成的 v1 JSON，包含 profiles、identity、samples、166 维 embedding 与可选 weight。C++ 使用相同 HSV 直方图、颜色矩和灰度外观描述。未指定注册库仍可显示身体小图，身份为 unregistered；显式配置但文件无效时启动失败，不能静默忽略配置。

这是轻量外观基线，未经真实场景准确率标定，不是训练后的猫咪 ReID 模型。抱猫、近似毛色、光线、背景和姿态都可能影响结果。当前要求最佳相似度至少 0.75、相对第二个身份领先至少 0.08，且同一轨迹有五次一致的有效匹配才显示名字。相似度不是正确概率。不自动把待确认图写回身份库，避免误识别污染样本。

## 只读接口

`/v1/context/current` 新增 `pet_portrait`：status、name、track_id、sequence、observed_at、similarity 和 thumbnail_available。status 为 matched、confirming、uncertain、unregistered、low_quality、ambiguous、held 或 unavailable。

`GET /v1/pet/thumbnail?sequence=N` 返回当前裁剪图的 JPEG，仅接受当前小图序号。图像最大边 320 像素，质量 80，禁止缓存。只保留内存中的当前图，最多保留三秒；更换序号、过期、离线时旧请求返回 404。原图、裁剪图和查询图片均不写入数据库或文件。历史时间线不带照片。

小图是检测框裁剪，可能包含背景或抱猫者的局部，不是身体分割图。网页明确标注采样时间；held 图提示来自刚才。连接失败或模式切换清除图像。模拟模式只展示占位提示，不伪造真实宠物照片。接口仍只监听回环地址，通过已有私有连接使用，不公开图库路径。

## 验收

1. 单只猫进入视野后应出现真实身体小图，未确认时显示身份待确认。
2. 连续匹配一致后才显示注册名字；模糊、远处、相似匹配不应强行给名字。
3. 猫转身或短暂遮挡时显示刚才的小图；超过三秒清除图片，离线立即清除。
4. 同时出现两只猫时不选择面积最大的一只来冒充当前身份。
5. 观察 Coco 和 Kui 各自的正面、侧面、背面与抱猫场景，人工记录误认和 unknown，不仅检查是否能显示名字。

自动测试覆盖有/无图库、JPEG 尺寸、连续确认、相同外观身份拒绝、模糊拒绝、过期清除、多猫以及网页的名称文本和离线清除。真实识别效果需用户提供可观察的猫咪场景验证。
