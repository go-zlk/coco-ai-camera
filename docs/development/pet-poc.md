# 单猫四态 POC 验证指引

本轮完成 C++ 功能链路：短期跟踪 → 活动/休息/不可见/离线 → SQLite 状态区间 → HTTP → 网页桌宠。板子离线时可完整运行模拟验证。真实精度、功耗和长时间稳定性仍需板端验收，不能用模拟结果代替。

## 本地运行

```bash
scripts/build_local.sh
./build/local/coco-poc
```

打开 http://127.0.0.1:8091/ 。默认读取 `tests/fixtures/pet_poc.csv`，模拟 54 秒的活动、休息、短暂漏检、不可见、离线与恢复。页头始终标记“模拟回放 · 非真实宠物数据”。回放结束后服务继续提供页面与历史，输入按超时变为离线，Ctrl-C 停止。

可指定独立数据库、端口、回放速率和网页文件位置：

```bash
./build/local/coco-poc --db /tmp/coco-poc.db --port 8091 --speed 1 --web-root web
```

速率范围为 0～1000（不包含 0）。加速只用于功能验证，不是推理性能。时间线使用输入中的模拟 UTC 时间，默认模拟日期是 2026-01-01。重复回放会追加状态事件；时间区间对同源重复或倒退时间不重复累计。真实服务和模拟回放应使用不同数据库。

## 四态规则 v0

| 状态 | 进入条件 |
|---|---|
| active | 单只已确认轨迹，中心速度超过画面尺寸的 3%/秒，或面积对数变化率超过 0.12/秒，连续约两秒 |
| resting | 单只已确认轨迹，20 秒观察窗口中中心范围不超过画面尺寸的 3%，面积比例不超过 1.25 |
| out_of_view | 在线输入连续五秒没有猫，沿用已有 presence 防抖 |
| offline | 五秒没有有效新帧；或本地模拟输入结束后超时 |
| unknown | 证据不足、轨迹变化、同时观察到多只猫或无法连续确认 |

短暂漏检最多保留上一次时序决策两秒，仍明确显示最后观察时间。活动状态有五秒短保持时间；身份改变或长缺口需要重新积累证据。阈值是未经过真实场景校准的功能基线，不是准确率结论。

摄像头转动也会制造位移，因此首个 POC 要求固定镜头。该规则不能确认睡眠、进食、情绪或健康状况。

## 时间线语义

`pet_intervals` 保存源、状态、置信度、UTC 开始/结束、最后确认时间和开放标志。状态不变时合并区间；重复时间不追加区间。状态变化时关闭前一区间。

- 每份状态最多外推五秒。更长采集空档、服务重启空档和未记录时间均为 unknown。
- 按 UTC 日期裁剪区间；不会把跨午夜的持续时间重复计入两天。
- 活动和休息统计不会包含 unknown、不可见或离线。
- 页面按请求时刻展示开放区间；历史保存在 SQLite 中，程序重启不丢已提交记录。
- 当前窗口决策按确认时间记录，不回填为推测的实际行为起点。

这仍是一个视频源、一只可见猫的 POC。轨迹不是持久宠物身份。模型版本、策略配置快照和事件幂等键尚需在正式评测数据格式中进一步完善。

## HTTP 与网页

- `GET /`：桌宠网页。
- `GET /v1/context/current`：含 pet_state、pet_confidence、来源、mode、最后观察、新鲜度和轨迹。
- `GET /v1/timeline?day=YYYY-MM-DD`：当天区间与各状态秒数，日期使用 UTC。
- `GET /v1/events`：最近状态变化。
- `GET /health`：当前健康快照。

真实 C++ 运行时也使用同一个页面和查询接口；默认静态文件目录为 `web`，可传 `--web-root`。API 仅监听本机回环地址。板端验证时可通过已有 SSH 工作流增加 API 端口转发；没有开放公网或消费者账号功能。

网页每秒轮询，断线后自动重试，过期状态显示离线。首版无需前端依赖或构建工具，使用轻量 JavaScript/CSS。WebSocket、TypeScript 前端工程化与局域网安装流程留到真实场景验收后。

## 功能验收

| 需求 | 已有验证 | 尚待验证 |
|---|---|---|
| 四态与 unknown | 固定框输入回放、时序规则测试 | 白天/夜间真实猫片段 |
| 短暂漏检与恢复 | 单帧漏检、轨迹恢复用例 | 真实转身与遮挡 |
| 当天时间线 | 重启、重复时间、跨午夜与空档测试 | 实机连续一天 |
| 网页与 API | 回环 HTTP 路由测试、本地浏览器检查 | 板端转发与手机布局实测 |
| 隐私 | 模拟输入和状态存储，无原始媒体写入 | 真实运行数据目录审计 |
| 设备恢复 | 本地结束输入/网页重试 | systemd、自启、12 小时稳定性 |
| 精度与性能 | 不以模拟数据声称准确率/FPS | 标注片段、P50/P95、功耗与温度 |

POC 功能验证的完成不等于原两周 MVP 的实机验收全部通过。板子恢复后，先把同一页面接到真实运行时，完成固定镜头单猫样例与人为断流，再决定是否调阈值或引入行为模型。
