# AI Desk Companion MVP 产品需求文档

状态：当前执行基线

版本：v0.1

日期：2026-10-03

## 1. 产品目标

AI Desk Companion 在用户工作或学习时，本地观察可测量的身体与活动状态，向 AI 提供实时、带时间范围和可信度的上下文。

第一版要验证一个问题：

> 当 AI 知道用户已经坐了多久、姿态是否变化、是否频繁离屏、是否长时间没有休息时，它给出的建议是否更相关、更及时？

产品价值不依赖自动提醒。用户主动提问时，系统也可以把当前上下文附加给 AI。

## 2. 目标用户与使用场景

### 目标用户

- 长时间使用电脑的软件工程师、设计师、研究人员和学生。
- 愿意在个人设备上运行本地视觉感知。
- 希望 AI 理解当前工作状态，同时不上传持续视频。

### 核心场景

1. 用户询问“我应该继续还是休息？”时，AI 获得连续在座时间与近期姿态趋势。
2. 用户询问“我今天专注得怎么样？”时，AI 获得工作时段、离座和明显分心趋势。
3. 用户长时间连续工作后，系统可以生成低打扰建议；用户可以关闭主动提醒。
4. 用户查看当天时间线，理解何时开始工作、休息、返回，以及姿态何时明显恶化。

## 3. MVP 范围

### 输入

- 一个固定桌面机位的 CSI 摄像头。
- 单用户。
- Jetson Orin Nano 本地推理。

### 输出

- 当前 `UserState` JSON。
- 当天 session、离座和姿态变化事件。
- 本地 HTTP Context API。
- 一个简单状态页，用于验证数据是否符合用户感受。

### 必须支持

- `presence`: `present / absent / unknown`。
- `session`: 当前连续在桌前时长。
- `posture`: `normal / forward / unknown`。
- `head_orientation`: `screen / down / side / unknown`，仅做粗粒度描述。
- 最近窗口内的前倾占比、屏幕朝向占比和离座次数。
- `source_health`: `online / stale / offline`。
- 状态的置信度、最后观测时间和数据新鲜度。
- 两小时持续运行。
- 原始视频默认不落盘。

## 4. 明确不做

- 不诊断疲劳、抑郁、焦虑、颈椎疾病或注意力障碍。
- 不宣称精确眼动或注视点追踪。
- 不识别屏幕具体内容。
- 不在 Milestone 0 自动控制灯光、空调或门锁。
- 不上传持续视频到云端。
- 不支持多人身份区分、多摄像头融合和跨房间追踪。
- 不先接 LLM，再倒推感知输出。

## 5. 用户体验

### 首次设置

用户只完成三件事：

1. 放置摄像头，使头、肩和上半身大部分时间可见。
2. 坐在正常工作位置 30–60 秒，建立冷启动参考。
3. 选择是否允许主动提醒；默认关闭。

系统自动检查画面质量并使用明确语言反馈：

- “已看到头部和双肩，可以开始。”
- “画面过暗，请增加桌面照明。”
- “肩部经常离开画面，请调整摄像头。”

### 日常状态页

页面只展示用户能理解的信息：

- 当前是否在桌前。
- 本次连续工作时长。
- 最近 20 分钟姿态趋势。
- 最近一次休息时间。
- 摄像头和数据是否正常。

置信度低时显示“暂时无法判断”，不显示强结论。

## 6. 状态与事件

### Session

- 连续检测到用户达到进入门槛后开始。
- 短暂漏检不会结束 session。
- 连续离开达到退出门槛后结束。
- 摄像头离线不会直接推断用户离开，而是结束可靠观测并标记数据过期。

### Posture

- 单帧关键点先归一化为与距离相对无关的几何特征。
- 时间窗口内投票后生成状态。
- `forward` 是相对冷启动姿态或个人基线的偏离，不使用固定像素距离。

### 领域事件

- `session_started`
- `session_ended`
- `user_left_desk`
- `user_returned`
- `posture_declining`
- `posture_recovered`
- `source_offline`
- `source_recovered`

事件只在稳定状态变化时产生，不能每帧写入一条重复事件。

## 7. 成功指标

### 工程验收

- 连续运行 2 小时无崩溃。
- 数据库和 `user_state.json` 持续更新。
- 摄像头断开后 10 秒内进入 `offline/stale`，恢复后自动继续。
- 内存持续增长小于 10%。
- 原始视频目录为空，除非用户显式启用调试采样。

### 感知验收

- Presence precision ≥ 95%。
- Presence recall ≥ 95%。
- 离座/返回事件时间误差中位数 ≤ 5 秒。
- 人工标注片段上的 posture 状态一致率 ≥ 80%。
- 稳定坐姿期间每小时无意义 posture 切换 ≤ 3 次。
- 无法可靠观察时正确输出 `unknown`。

这些是进入下一阶段的门槛，不是当前已经达到的结果。

### 产品验证

对同一批问题进行 A/B：

- A：只有用户问题。
- B：用户问题 + 当前/历史 Context。

用户盲评建议的相关性、时机和打扰程度。只有 B 稳定优于 A，才继续投入 LLM Coaching。

## 8. 隐私原则

- 默认只在 Jetson 本地处理视频。
- 持久化内容为低维状态、事件、聚合指标和模型版本。
- 调试图像必须显式开启、设置保留时间，并能一键删除。
- API 默认只监听局域网，远程访问后续增加认证。
- 状态记录提供暂停、清空和保留期限设置。

## 9. 发布门槛

Milestone 0 完成需要同时满足：

1. 真实 CSI 摄像头运行。
2. 两小时记录文件与资源报告。
3. 固定标注片段上的状态评测。
4. 当前 Context API 可查询。
5. README 中的启动方法可由另一台机器复现。
6. 失败案例和当前限制被明确记录。
