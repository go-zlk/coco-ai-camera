# 消费者产品开发路线

状态：当前产品路线；首个猫咪桌宠场景仍需市场验证

## 产品边界

最终用户是普通消费者。用户获得的是容易安装、低打扰、值得日常保留的陪伴/生活帮助体验。Jetson、Context Runtime、状态机和 API 是内部实现，原型阶段可以复杂，消费者版本不能要求用户接触终端、手工部署推理模型或维护开发板。

首个候选产品：上班时通过真实猫咪活动驱动桌面/手机桌宠，并查看当日状态时间线。详见[单猫候选 MVP](mvp-spec-single-cat.md)。

## 阶段路线与验收

### 0. 需求验证与可演示原型（两周）

- 访谈 12–15 位目标养猫人，涵盖持续使用、很少使用和停用摄像头的人。
- 演示真实猫咪摄像头状态与桌宠同步；明确区分真实能力和模拟内容。
- 同步完成 Jetson 上单摄像头到猫咪状态/事件/本地展示的最小链路。
- 记录设置负担、状态误判、unknown、离线和不可见案例。

**继续条件：**至少 6 人能描述最近一周重复发生的实际需求；至少 5 户愿意参与两周测试；至少 3 户愿意实际付费或支付可退款订金。未达标则调整/停止当前切入口。

### 1. 5–10 户家庭封闭试用（第 3–6 周）

- 一个摄像头、一只猫、电脑或手机端。
- 显示活动、休息、暂时不在视野、设备离线；低置信度显示“正在观察”。
- 提供当前状态、最后观察时间和一天时间线。
- 测 14 天：首次设置用时、每日主动使用、第二周留存、误判、桌宠关闭、用户情绪反馈。

**继续条件：**70% 的试用家庭能在 5 分钟内独立完成初次设置；60% 在第二周最后三个工作日仍主动使用；至少 3 户实际付款且未退款。此为小样本内部门槛，不是行业标准。

### 2. 消费者付费 MVP（第 2–3 个月）

- 先支持目标用户常用且可稳定接入的摄像头/输入方式，不承诺兼容所有品牌。
- 加入简单配网、机位检查、隐私控制、离线恢复、数据删除和状态纠错。
- 20–50 户付费试用，衡量激活率、四周留存、退款率、安装支持成本和推荐行为。
- 只有用户确实需要且愿意支付后，才增加远程访问、手机/手表、多猫与云同步。

### 3. 拓展到更多日常生活问题（第 4–12 个月）

只有宠物场景显示真实留存和付款后，才向其他家庭关系或日常任务扩展。每次扩展都以明确的人群和高频问题开始，保持简单设置、用户控制和数据透明。

## 普通用户体验要求

- 首次安装目标不超过 5 分钟；安装失败能自助修复或清楚说明原因。
- 首屏直接呈现猫咪状态、更新时间和连接情况，不让用户读模型置信度术语。
- 可见/不可见、unknown 和设备离线明确区分；不以推测冒充实时事实。
- 默认本地处理，不默认保存原始视频；采集可暂停，历史可删除。
- 动画和通知都可关闭；不通过制造焦虑促使用户频繁查看。
- 软件应支持面向家庭用户的自动更新和安全恢复；Jetson 开发板只作为研发设备。

## 当前待证伪的产品假设

1. 养猫人真正反复遇到“想知道猫在做什么但不想打开摄像头”的时刻。
2. 桌宠同步比摄像头 AI 摘要、照片或简单状态卡片带来更强的情感价值。
3. 用户不因误判、相机权限或常驻运行而感到被打扰。
4. 用户能在少量设置后自行使用，并且愿意持续付费。

若假设 2 不成立，保留宠物状态/时间线，改为更直接的呈现；若 1/4 不成立，不因技术已投入而继续扩大产品。
