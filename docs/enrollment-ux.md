# 低负担身份注册体验

## 设计原则

用户不应该理解 embedding、阈值或数据集，也不应该手动拍几十张照片。注册流程只需要用户完成两件事：给身份命名，以及确认系统挑出的代表性样本。

```text
系统自动采集与筛选
        ↓
用户确认“这是 Coco”
        ↓
后台持续补充样本
```

## 宠物注册：两阶段流程

### 冷启动引导（约 20–30 秒）

1. 用户点击“添加宠物”，输入 `Coco`。
2. 页面提示把猫放在摄像头前自然走动，不要求摆拍。
3. 系统从连续视频中自动检测猫，按时间和视角去重，只保留 8–12 个高质量样本。
4. 页面展示 4–6 张代表图，用户确认“这些都是 Coco”。
5. 对 `Kui` 重复一次；如果只有一只猫，也可以稍后再添加。

采样质量门槛：检测置信度、目标框面积、清晰度、遮挡比例、与已有样本的外观差异。重复帧和严重遮挡帧不进入 gallery。

### 被动补充（默认开启）

运行几天后，系统从 `unknown` 或低相似度轨迹中挑选代表片段，生成候选卡片：

```text
发现一个可能的新身份
[样本 1] [样本 2] [样本 3]

这是 Coco / Kui / 新宠物 / 忽略
```

用户一次点击即可确认。确认后的样本加入对应 gallery；“忽略”样本进入负例集合，降低下次误匹配。

## 人员注册：门禁式流程

人员注册需要更高的安全门槛，但仍不要求用户上传照片：

1. 用户输入姓名并开始注册。
2. 页面引导正面、左转、右转和眨眼，约 10 秒。
3. 系统自动检查人脸尺寸、清晰度、光照和活体动作。
4. 用户确认代表帧后，本地保存多个 embedding 原型。
5. 新设备或新光照下首次识别到该人时，要求再次确认再扩充 gallery。

人员身份默认只用于展示和查询。接入门锁、报警或家电控制前，必须另外启用授权策略、活体检测和二次确认。

## 失败时的用户体验

- 样本不足：显示“再观察一会儿”，不要求重新拍照。
- 两只猫相似度过高：显示“暂时无法区分”，进入候选确认，不强行命名。
- 目标被遮挡：保留轨迹但不更新身份 gallery。
- 识别置信度下降：显示 `unknown` 或“需要确认”，不编造身份。
- 用户撤销身份：立即停止匹配，历史事件保留匿名 ID 或按设置删除。

## 推荐交互页面

### 身份列表

显示名称、类型、最近出现时间、样本数量、识别状态和停用按钮。

### 添加身份

只显示：名称、类型、开始观察、确认样本。高级设置（阈值、模型版本）默认折叠。

### 候选确认

以照片卡片和短轨迹摘要为主，不显示技术术语：

```text
今天 14:03 发现一个未命名的猫
确认它是 Coco 吗？
[是 Coco] [是 Kui] [不是这两只] [忽略]
```

## 数据策略

- 原始视频只做短期缓存，采样裁剪和 embedding 经过质量筛选后再保留。
- gallery 保存多个代表向量，而不是单张“标准照”。
- 每个样本记录来源时间、摄像头、模型版本和用户确认来源。
- 默认本地处理；跨设备同步需要单独开关。
