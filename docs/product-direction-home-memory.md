# AI Home Memory 产品方向与演进路线

## 1. 产品定位

本工程的长期目标不是再做一个普通摄像头或录像机，而是让家庭能够回答：

> **“我的家发生过什么？”**

产品暂定为 **AI Home Memory（家庭记忆 AI）**。摄像头是第一类传感器，Jetson 是本地感知与事件处理节点。系统持续观察家庭环境，维护可查询的世界状态，并在需要时给出带证据和置信度的回答。

核心能力按以下顺序演进：

```text
Remember   记住发生过什么
    ↓
Understand 理解环境和长期变化
    ↓
Act        在用户授权后执行动作
```

“语义事件 + 关键帧 + AI 生成回放”属于后续的存储与回顾能力，不能替代事实记录，也不作为第一版产品定位。

## 2. 为什么先做猫咪 MVP

当前的单摄像头、单猫、四状态 MVP 是一个垂直切片，而不是最终产品。它用较小的范围验证四个基础问题：

1. Jetson 能否长时间稳定采集并运行推理。
2. 系统能否把连续观测稳定地转换成状态区间和时间线。
3. 网页端能否把实时状态和历史事件呈现出来。
4. 设备离线、目标不可见和推理异常时，产品是否诚实地表达不确定性。

猫咪状态是最容易观察和展示的入口。成功后，感知层可以替换为通用实体和事件模型，扩展到钥匙、遥控器、苹果、人员和房间活动。

## 3. 产品分阶段路线

### 阶段 0：Pet Activity Vertical（当前两周）

范围：单摄像头、单猫、`active / resting / out_of_view / offline` 四种用户状态，网页桌宠和一天时间线。

交付重点是稳定性、时间线正确性、状态切换防抖和可演示性。暂不追求通用物体记忆。

### 阶段 1：Home Memory MVP

固定一个房间，选择 3–5 个容易标注的实体，例如钥匙、遥控器、苹果和背包。新增：

- 实体、地点和关系的注册。
- `picked_up / moved / placed / entered / left` 等事件。
- 事件对应的关键帧、时间戳、来源摄像头和置信度。
- “钥匙最后在哪里？”、“谁移动了遥控器？”、“什么时候发生的？”等查询。

第一版回答必须来自结构化事件和世界状态；找不到证据时返回“未知/未观察到”，不能让语言模型补写事实。

### 阶段 2：Understand

在事件之上生成日、周摘要和趋势，例如猫的活动规律、人员在家的时间、物体移动频率。摘要必须能回链到原始事件和关键帧。

### 阶段 3：Act

接入 Home Assistant、米家或 Matter 等智能家居系统。所有自动动作先采用“建议 + 用户确认”，在稳定性和误报率达到门槛后再开放有限的自动化。

### 阶段 4：Semantic Replay

保留少量关键帧、动作序列和环境状态，按语义生成回顾视频。生成内容必须单独标记为 `reconstruction`，与 `fact`（原始观测）分开保存。

## 4. 统一领域模型

后续代码应逐步从 `CatState` 抽象到以下通用对象：

```text
Entity       人、猫、钥匙、房间、家具
Place        房间、桌面、柜子、区域
Observation  某时刻由某传感器得到的观测
Event        实体或地点发生的动作/变化
Relation     entity 在 place、entity 携带 object 等关系
Evidence     关键帧、短视频片段、模型版本、来源设备
Confidence   置信度、可见性、数据新鲜度
```

推荐事件记录至少包含：

```text
event_id, event_type, actor_id, subject_id, from_place, to_place,
start_time, end_time, confidence, evidence_id, model_version
```

## 5. Jetson、客户端和可选服务的边界

### Jetson Orin Nano

- CSI/RTSP 视频接入与健康监测。
- GStreamer 解码、采样和预处理。
- TensorRT/YOLO 推理、跟踪和状态估计。
- 本地事件写入 SQLite，保存关键帧索引。
- 提供局域网 API/WebSocket，断网时继续工作。

### 网页端

- 显示当前状态、设备状态和时间线。
- 提供查询、筛选和证据查看。
- 不承担持续推理，不把浏览器当作数据源。

### PC/云端（后续可选）

- 模型训练、离线评估和模型转换。
- 更重的视觉语言模型或语义检索。
- 跨设备同步；默认不上传原始视频。

## 6. 隐私与事实边界

系统默认本地优先：原始视频短期循环保留，结构化事件和少量关键帧长期保留。每个回答都应能区分：

- **Fact**：摄像头实际观测并写入的事实。
- **Inference**：根据多次观测推断的状态。
- **Reconstruction**：模型生成的回顾内容。

这三者不能混在同一条数据或同一句无标记的回答中。

## 7. 继续投入前的验证指标

完成猫咪 MVP 后，用以下指标决定是否进入 Home Memory 阶段：

- 连续运行 8 小时无崩溃，数据无明显丢失。
- 状态区间的开始/结束时间误差小于 1 分钟。
- “当前状态”和“今天时间线”查询成功率达到 90% 以上。
- 断网恢复后事件不重复、不乱序。
- 对“不可见”和“离线”不做虚假推断。

Home Memory MVP 再增加：物体最后位置查询的证据命中率、事件抽取准确率、用户重复查询率和原始视频存储减少比例。

## 8. 现在的下一步

当前硬件链路已经确认：Jetson Orin Nano、JetPack 6.2.1、TensorRT 10.3、CSI 采集和真实画面均正常。现阶段的实际阻塞点是模型文件尚未放到 Jetson，因此先完成 `yolov8n.pt` 的下载和传输，再运行猫检测；同时在代码命名和数据结构上逐步使用 `Entity/Event`，保留猫作为第一个适配器。

现在不做云端账号体系、跨家庭多摄像头、米家控制、通用大模型常驻、生成式视频回放和大规模训练。这些工作要等本地感知、事件时间线和查询闭环被验证后再进入排期。
